<objective>
Deliver the SIGINT -> SIGTERM -> SIGKILL cancellation primitive that closes Phase 10's success criterion 3: re-utterance race (Pitfall #10). When the user starts a new utterance while Claude is still working, the bridge must stop the in-flight child promptly, drain any pending stdout up to the interruption point, surface a `failure / cancelled` outcome, and free up the bridge state for a clean `--resume <sid>` continuation on the next turn.

Purpose: LOOP-07 — the user can cancel an in-flight Claude Code job via session.cancel(); SIGINT reaches the child within 50 ms; the events$ AsyncIterable closes cleanly; and a subsequent createClaudeSession with `resumeSessionId` set to the previous session.sessionId starts a NEW child via `--resume <sid>`, preserving conversation context across the cancel boundary.
Output: A cancellation primitive that composes with Plan 10-02's session.ts. session.cancel() returns a Promise<ProcessExitEvent>. Idempotent. Drain-aware (stdout written before exit is still parsed and emitted). Outcome attribution: cancelled overrides exit_code and tool_error per Plan 10-02's deriveOutcome contract. Tests use vitest fake timers to verify the 1 s + 2 s escalation deadlines without sleeping in real time.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> session.cancel() | Caller is the Phase 12 session.ts orchestrator. Cancellation is triggered by the user pressing PTT again mid-job. No untrusted input crosses this boundary — it's a void method call. |
| session -> child via signals | The bridge sends OS signals (SIGINT, SIGTERM, SIGKILL) to the child PID. Signal escalation timing is fixed (1 s + 2 s) and is not caller-tunable in v1.2. |
| pending stdout drain -> events$ | Between cancel() and child exit, stdout chunks may carry partial assistant text. Plan 10-02's line parser + wire mapper apply the same defences here as in normal flow. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-13 | Denial of Service | Child ignores SIGINT | mitigate | Escalation state machine: SIGINT (immediate) -> SIGTERM (+1000 ms) -> SIGKILL (+2000 ms). SIGKILL cannot be ignored by the child. Cancellation always terminates within ~3 s upper bound. |
| T-10-14 | Race Condition | Double cancel from concurrent code paths | mitigate | Per-session idempotency cache (`cancelPromise`) and per-child WeakMap inside cancelChildProcess. Two concurrent cancel() calls return the same Promise; child.kill is invoked exactly once per signal across all callers. |
| T-10-15 | Information Disclosure | Stale assistant text leaks into next turn | mitigate | events$ terminates after ProcessExit (the existing Plan 10-02 contract). session.lastTurnText reflects whatever was accumulated up to the interruption point; Phase 12's session orchestrator is responsible for discarding the cancelled turn's text rather than routing it to TTS (Pitfall #10 "stash event" — the cancelled turn's output is discarded from the spoken-completion queue). This plan ships the surface that lets Phase 12 distinguish cancelled outcomes via outcome.reason === "cancelled". |
| T-10-16 | Tampering | Caller-supplied setTimeout/clearTimeout deps | accept | The deps injection is for vitest fake timers in tests. Production callers do not pass deps; the bridge falls back to global setTimeout/clearTimeout. Documented as `@internal` in JSDoc. |
| T-10-17 | Repudiation | Cancelled outcome attribution after a natural exit | mitigate | Test 9 enforces: cancel() called AFTER a natural exit does NOT retroactively flip outcome.reason to "cancelled". This prevents a buggy caller from mis-attributing a failed run to user intent. |
