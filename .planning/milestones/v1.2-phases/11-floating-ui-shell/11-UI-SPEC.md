# Phase 11 — UI Design Contract

> Visual and interaction contract for the Achilles floating shell. Generated by gsd-ui-researcher (autonomous mode against locked CONTEXT.md). Verified by gsd-ui-checker.

This is a **non-standard UI surface**: a 260x260 px frameless transparent always-on-top Electron panel window, not a page-oriented web app. The contract below extends the standard tokens (spacing/typography/color) with five domain-specific sections (visual states, layout grid, interaction model, accessibility, permissions, settings, errors, component contract, testability). Phase 11 ships against a mocked state machine so every visual is verifiable without the voice loop.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla CSS modules) |
| Preset | not applicable — Electron renderer, no shadcn |
| Component library | none (hand-rolled React 18.3 components) |
| Icon library | inline SVG only (no icon font; minimises bundle) |
| Font | system stack — `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` |
| Animation | CSS transitions + `requestAnimationFrame` for amplitude-driven scaling; no framer-motion dependency in Phase 11 (revisit if breathing animation feels janky) |
| Bundle target | < 200 KB renderer JS + < 30 KB CSS gzipped |

**Why no shadcn:** The Phase 11 surface is a 260x260 px transparent panel with five custom visual states. shadcn primitives (Button, Card, Popover) are page-oriented and assume light/dark surface backgrounds — they do not fit a frameless transparent HUD. The settings popover (10. below) is the only "shadcn-shaped" surface and is small enough (~120 lines) to hand-roll without dragging in Radix + components.json.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps inside the transcript area, waveform bar gap |
| sm | 8px | Drag-handle inset, settings popover row padding |
| md | 16px | Default padding inside the settings popover, error overlay copy padding |
| lg | 24px | Default window edge margin from screen corner |
| xl | 32px | Permission overlay vertical rhythm |

Exceptions: **none**. The window is too small for `2xl` (48px) or `3xl` (64px) tokens; those tokens are reserved for future full-screen settings UI deferred to Phase 13.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 13px | 400 (regular) | 1.5 | Transcript text (partial + committed) |
| Label | 11px | 500 (medium) | 1.3 | Settings popover labels, hotkey display |
| Heading | 15px | 600 (semibold) | 1.2 | Settings popover title, permission overlay heading |
| Display | n/a | n/a | n/a | No display type — the circle is the focal element |

**Rationale:** Three sizes (13/11/15) and two weights (400/600 — `500` for labels is an intermediate-weight aesthetic choice for one role; if the system stack does not have a true `500` it gracefully maps to `400` on macOS/Windows). All sizes are readable at default macOS DPI without being visually heavy at 260x260 px.

## Color

Color tokens are expressed as CSS custom properties so Phase 12 (and future themes) can override without touching components. All declared in `apps/achilles/src/renderer/styles/tokens.css`.

### Base palette (neutral)

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--achilles-bg` | `rgba(20, 22, 28, 0.85)` | Window backdrop (semi-transparent dark — works on both light and dark desktops) |
| Secondary (30%) | `--achilles-surface` | `rgba(28, 30, 38, 0.92)` | Settings popover background, permission overlay background |
| Text primary | `--achilles-text` | `#E8EAED` | Transcript committed text, settings labels |
| Text secondary | `--achilles-text-dim` | `rgba(232, 234, 237, 0.7)` | Transcript partial text |
| Border | `--achilles-border` | `rgba(255, 255, 255, 0.08)` | Settings popover divider, drag handle hairline |

### State accents (10% accent reserved per state)

Each state owns exactly one accent color. The accent renders on the circle and glow only; transcript text never picks up accent.

| State | Token | Value | Reserved for |
|-------|-------|-------|--------------|
| Idle | `--achilles-idle` | `#5F6471` (neutral cool grey) | Idle ring, breathing circle |
| Listening | `--achilles-listening` | `#3DD68C` (neon green) | Listening circle, waveform bars during mic capture |
| Processing | `--achilles-processing` | `#F5A623` (amber) | Processing rotating ring |
| Speaking | `--achilles-speaking` | `#4A9EFF` (calm blue) | Speaking circle, waveform bars during TTS playback |
| Error | `--achilles-error` | `#FF4D4F` (alarm red) | Error ring, error banner border |

### Destructive

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Destructive | `--achilles-destructive` | `#FF4D4F` (matches error) | "Reset window position" confirmation only (no other destructive actions in Phase 11) |

**Accent reserved for:** circle ring, circle inner fill (radial gradient), waveform bars, error banner border. **Never** applied to transcript text, drag handle, or settings labels — those stay neutral so the accent is unambiguous as the state signal.

### Opacity rules

| Element | Opacity | Notes |
|---------|---------|-------|
| Window background | `0.85` | Semi-transparent over desktop |
| Settings popover | `0.92` | Slightly more opaque for legibility |
| Permission overlay | `0.95` | Near-opaque — critical user copy must be legible |
| Transcript partial text | `0.7` | LOOP-02 requirement |
| Transcript committed text | `1.0` | LOOP-02 requirement |
| Transcript auto-fade after 15s idle | linear `1.0 → 0` over 1500ms | LOOP-02 requirement |
| Circle glow during idle | `0.4` | Subdued breathing |
| Circle glow during listening | `0.7` → up to `1.0` (amplitude-driven) | Pulse signal |

## 1. Visual States Map (UI-02, UI-03, UI-04)

The five states are visually distinct enough to identify at a glance from 6 feet without text labels. Each state's contract:

### State: idle

| Aspect | Specification |
|--------|---------------|
| **Circle** | Diameter 96px. Solid neutral fill `--achilles-idle` at 0.4 opacity. Breathing scale `0.95 ↔ 1.05` over 2000ms using `ease-in-out`. Soft ring 1px at `--achilles-idle` 0.6 opacity. **60 fps** (CSS transform; GPU-composited). Breathing pauses when window is hidden (`document.visibilityState !== 'visible'`) to save CPU. |
| **Waveform** | 32 bars, all at 2px height (silent baseline), color `--achilles-text-dim`. **No animation** — bars are static at idle. |
| **Background tint** | `--achilles-bg` (rgba dark @ 0.85). |
| **Transcript area** | Last committed transcript visible, fading to 0 opacity 15 seconds after the most recent commit. If empty, area is fully transparent. |
| **Cursor** | Default arrow over the circle (clickable); `grab` cursor over the drag handle strip. |
| **Jury-test** | "From 6 feet, this looks like a small dim grey orb gently breathing on a dark backdrop — clearly inactive but alive." |

### State: listening

| Aspect | Specification |
|--------|---------------|
| **Circle** | Diameter 96px. Fill is a radial gradient from `--achilles-listening` at the center fading to 50% opacity at the edge. Scale = `0.9 + rms * 0.5` (where rms is normalized 0..1 from the mic AnalyserNode); update every animation frame. Outer glow box-shadow: `0 0 20px var(--achilles-listening)` at opacity tracking `0.7 + rms * 0.3`. **60 fps via `requestAnimationFrame`**, RMS sampled at 20 fps from AnalyserNode (every 50ms) and interpolated. |
| **Waveform** | 32 bars driven by `AnalyserNode.getByteFrequencyData()` on the mic stream. Bar color `--achilles-listening`. Bar height = `data[i] / 255 * 64px`. Animated at **20 fps** (50ms tick). |
| **Background tint** | Same `--achilles-bg`. Optionally a 2px outer-glow ring around the entire window at `--achilles-listening` opacity 0.3 (very subtle — guards Pitfall #15 "is Achilles capturing?" worry). |
| **Transcript area** | Partial transcripts render in real time at opacity 0.7 (`--achilles-text-dim`). Committed (final) lines snap to opacity 1.0 (`--achilles-text`). Newest at the bottom, oldest scrolled out of view (max 3 lines visible). |
| **Cursor** | Default arrow; click-on-circle behaves as hotkey (commits the in-flight utterance in toggle mode, releases in PTT mode). |
| **Jury-test** | "From 6 feet, this looks like a bright green pulsing orb with bars dancing next to it — clearly the mic is hot." |

### State: processing

| Aspect | Specification |
|--------|---------------|
| **Circle** | Diameter 96px. Solid fill `--achilles-bg` (transparent dark). Indeterminate rotating ring 3px thick at `--achilles-processing`, 270deg arc, rotating clockwise at one full rotation per 1200ms (linear). **60 fps** via CSS `@keyframes spin`. **No scale change** — circle stays at scale 1.0 to be visually distinct from listening/speaking. |
| **Waveform** | Bars at low fixed height (4px each) with subtle vertical shimmer — height oscillates `4px ↔ 8px` per bar on staggered 800ms cycle. Color `--achilles-processing` at 0.5 opacity. This communicates "active but not amplitude-driven." |
| **Background tint** | Same `--achilles-bg`. |
| **Transcript area** | Last committed transcript stays visible (no fade) — the user just spoke it; they want to confirm what Achilles heard while Claude works. |
| **Cursor** | Default arrow; clicking the circle in this state is a **cancel** gesture in Phase 12 (sends SIGINT to Claude). Phase 11 mocks this as a state transition `processing → idle` for testability. |
| **Jury-test** | "From 6 feet, this looks like an amber spinning ring — clearly working, not listening." |

### State: speaking

| Aspect | Specification |
|--------|---------------|
| **Circle** | Diameter 96px. Radial-gradient fill from `--achilles-speaking` at the center. Scale = `0.9 + ttsRms * 0.5`, amplitude-driven by the TTS playback AnalyserNode. Glow box-shadow `0 0 20px var(--achilles-speaking)` opacity 0.6. **60 fps RAF**; RMS tick at 20 fps. |
| **Waveform** | 32 bars, source = TTS playback AnalyserNode. Bar color `--achilles-speaking`. Same scaling as listening but the source is the speaker output. **20 fps**. |
| **Background tint** | Same `--achilles-bg`. |
| **Transcript area** | Fades out 1 second into speaking state — the user is hearing the response, not reading. (Optional Phase 12 enhancement: render the spoken text as captions. Phase 11 simply hides.) |
| **Cursor** | Default; click-on-circle = cancel TTS (state to idle). |
| **Jury-test** | "From 6 feet, this looks like a calm blue pulsing orb with blue bars dancing — Achilles is speaking back." |

### State: error

| Aspect | Specification |
|--------|---------------|
| **Circle** | Diameter 96px. Solid stroke 3px `--achilles-error`, no fill (transparent center). Subtle shake animation: translate `-2px ↔ 2px` on X axis over 80ms, dampened over 600ms then static. No scale change. **30 fps** for the shake (`@keyframes shake`). |
| **Waveform** | 32 bars all at 2px height, color `--achilles-error` at 0.3 opacity. Static. |
| **Background tint** | Same `--achilles-bg`. An `<ErrorBanner>` is rendered above the circle (see Layout Grid below). |
| **Transcript area** | Hidden — the error overlay takes the visual focus. |
| **Cursor** | Pointer over the error banner's "Dismiss" button. |
| **Jury-test** | "From 6 feet, this looks like a red-ringed orb with a red banner above it — clearly something is broken." |

## 2. Layout Grid (UI-01)

Window is 260 px square. All coordinates are in window-local pixels (origin top-left). Layout is a vertical stack with anchored regions:

```
0px ┌────────────────────────────────────────┐
    │  drag handle strip (0–30px high)       │  ← invisible drag region; cursor: grab
30  ├────────────────────────────────────────┤
    │                                        │
    │                                        │
    │             ┌────────┐                 │  ← circle: 96px diameter,
    │             │ CIRCLE │                 │     centered horizontally,
    │             └────────┘                 │     vertical center y=98
    │           [bar bar bar...]             │  ← waveform: 32 bars,
146 ├────────────────────────────────────────┤     y=148..170, bar width=4px,
    │                                        │     gap=2px, total span=190px,
    │  Transcript:                           │     centered horizontally
    │    [partial @ 0.7 opacity]             │
    │    [committed @ 1.0 opacity]           │  ← transcript area: y=176..240
240 ├────────────────────────────────────────┤
    │      [settings ⋯ button: right edge]   │  ← affordance: y=246, right=12
260 └────────────────────────────────────────┘
```

### Exact pixel positions

| Element | Position | Size | Notes |
|---------|----------|------|-------|
| Drag handle | `top: 0`, `left: 0` | `260 × 30` | Invisible region; `-webkit-app-region: drag` on the outer div; child interactive elements re-enable click via `-webkit-app-region: no-drag` |
| Circle | center `x: 130, y: 98` | `96 × 96` | SVG circle with radial-gradient fill; CSS transform scales it |
| Waveform | `top: 148`, `left: 35` | `190 × 22` | Canvas2D element; 32 bars of 4px width, 2px gap, max bar height 22px |
| Transcript area | `top: 176`, `left: 16`, `right: 16` | `228 × 64` | Plain text; max 3 lines visible; overflow hidden; oldest scrolled out |
| Settings affordance | `bottom: 8`, `right: 12` | `16 × 16` | SVG dot-dot-dot (⋯) at `--achilles-text-dim`; right-click on circle is the primary path; this is a visible fallback |
| Error overlay surface | `top: 0`, `left: 0` | `260 × 90` | Renders as a banner above the circle when state=error; pushes other elements down/hides them |
| Permission overlay surface | `top: 0`, `left: 0` | `260 × 260` | Full-window overlay (UI-07) replacing the rest of the layout when permission state is `denied` or `restricted` |

### Pointer-events boundary (clicks pass through)

```
.window-root { pointer-events: none; /* default — clicks pass to apps behind */ }
.drag-handle, .circle, .waveform, .transcript-area,
.settings-affordance, .error-banner, .permission-overlay,
.settings-popover {
  pointer-events: auto; /* re-enable on the visible elements */
}
```

This matches the locked decision in CONTEXT.md "HTML body: `pointer-events: auto` only on the visible circle + drag handle; rest is `pointer-events: none`."

### Multi-monitor positioning

- Default position on first launch: top-right of the **primary display**, 24 px inset from the right and top edges.
- Position persists in `electron-store` under key `windowPosition: { x: number, y: number }`.
- On startup, if the persisted position is off-screen (e.g., the secondary monitor was disconnected), fall back to the default top-right of the primary display and log a `[achilles]` warning.
- Snap-to-edge: **not in Phase 11** — adds complexity for marginal value; defer to v1.3.

## 3. Motion & Animation

| Animation | Easing | Duration | Notes |
|-----------|--------|----------|-------|
| Breathing (idle circle) | `ease-in-out` | 2000ms full cycle (1000ms in, 1000ms out) | Scale `0.95 ↔ 1.05`. Pauses when window is hidden. |
| State transition (color + glow swap) | `--motion-ease-out` (`cubic-bezier(0.2, 0.7, 0.3, 1)`) | 350ms | When state changes, color tokens transition over 350ms. Scale change is instant; only color crossfades. |
| Listening/speaking amplitude pulse | linear (RAF-driven) | per-frame | No easing — direct amplitude mapping. |
| Processing rotating ring | linear | 1200ms per full rotation | `@keyframes spin`. |
| Processing waveform shimmer | `--motion-ease-in-out` | 800ms, staggered per bar | Subtle. |
| Error shake | `ease-out` (dampened) | 600ms total | Shake amplitude decays over the 600ms. |
| Settings popover open/close | `--motion-ease-out` | 150ms | Slide-up + fade. |
| Permission overlay enter | `--motion-ease-out` | 250ms | Fade-in. |
| Transcript fade-out (idle 15s rule) | linear | 1500ms | LOOP-02. |

**Reduced motion (`prefers-reduced-motion: reduce`):** all durations collapse to 0ms. Breathing animation disabled (scale fixed at 1.0). Amplitude-driven scaling still works (it's user-initiated mic input, not decorative motion) but the color crossfade snaps instantly.

## 4. Interaction Model (UI-05, UI-06)

### Hotkey (global)

| Mode | Default key | Behavior |
|------|-------------|----------|
| Press-to-toggle (default) | `Cmd+Shift+A` (macOS) / `Ctrl+Shift+A` (Windows/Linux) | Single press: `idle → listening`. Second press: `listening → processing` (commits the in-flight utterance to the mock state machine). |
| Push-to-talk | same key | Key down: `idle → listening`. Key up: `listening → processing`. |

Mode is persisted in `electron-store` under `hotkeyMode: 'toggle' | 'pushToTalk'`. The hotkey key itself is persisted under `hotkeyKey` as an Electron accelerator string (default `'CommandOrControl+Shift+A'`).

**Visual feedback for hotkey activation:**
- The instant the hotkey fires, the circle transitions color to `--achilles-listening` over 350ms. The state transition is the only feedback; no additional flash or sound (would break the "ambient utility" goal).
- In PTT mode, while the key is held the circle stays in listening state regardless of mic amplitude (the user might be pausing mid-sentence). On key-up the transition fires.

### Drag

- Top 30 px of the window is the drag region (`-webkit-app-region: drag`).
- Cursor over the drag region: `grab` (becoming `grabbing` during drag).
- Drag emits `update-window-position { x, y }` IPC from renderer to main on `mouseup`; main writes to `electron-store`.
- Drag is **not throttled** (the window itself moves under the OS — the only IPC is on release).
- Multi-monitor: dragging onto a secondary display is allowed; the persisted position is the absolute screen coordinate.

### Click on circle

- **Idle:** equivalent to hotkey press → `listening`.
- **Listening:** equivalent to hotkey press → `processing` (toggle mode) or no-op (PTT mode, since PTT requires a held key).
- **Processing:** cancel → `idle` (Phase 12 sends SIGINT to Claude; Phase 11 mocks this).
- **Speaking:** cancel TTS → `idle` (Phase 12 stops playback; Phase 11 mocks).
- **Error:** no-op (use the banner's dismiss button instead).

### Right-click on circle

- Opens the `<SettingsPopover>` anchored to the right of the circle (popover top-left at circle center + 60px right).
- If the popover would overflow the window edge, anchor to the left of the circle instead.

### Click pass-through

Elements outside the visible UI elements (drag handle, circle, waveform, transcript area, settings affordance, overlays) have `pointer-events: none`. A click in the empty corners of the 260x260 window passes through to whatever app is behind it. This honors the locked CONTEXT.md decision.

### Cancel during listening

In **toggle mode**, pressing the hotkey while listening commits the utterance (`listening → processing`). To **abort** without commit, right-click → settings popover → "Cancel utterance" (Phase 11). This is a clunky path acknowledged for v1.2 hardening in Phase 14 (LOOP-07 owns the formal cancel gesture for in-flight Claude jobs; in-listening cancel is a Phase 14 deferred polish).

In **PTT mode**, releasing the key always commits. To abort, the user can right-click the circle while holding the key, then the popover's cancel triggers `listening → idle` without entering processing.

## 5. Accessibility

| Concern | Implementation |
|---------|---------------|
| **Reduced motion** | `@media (prefers-reduced-motion: reduce)` collapses breathing, state-color crossfade, shake, shimmer, and popover slide durations to 0ms. Amplitude-driven scaling (user-initiated mic input) is exempt because it conveys functional state, not decoration. |
| **High-contrast mode** | Windows `prefers-contrast: more` and macOS Increase Contrast: borders thicken from 1px to 2px; the circle's outer ring widens from 1px to 3px; transcript text contrast token bumps `--achilles-text` from `#E8EAED` to `#FFFFFF`. |
| **Keyboard navigation for settings popover** | The popover (`<SettingsPopover>`) is a focus-trapping element. Tab cycles through: mode toggle → hotkey capture button → reset window position button → close. Esc closes the popover. Arrow keys move within the mode toggle (`toggle` vs `pushToTalk`). |
| **VoiceOver / NVDA labels** | The circle has `role="status"` and `aria-live="polite"` with `aria-label` updated on state change: `"Achilles idle"`, `"Achilles listening"`, `"Achilles processing"`, `"Achilles speaking"`, `"Achilles error: {message}"`. Partial vs committed transcripts use `aria-live="polite"` (partial) and `aria-live="assertive"` (committed). |
| **Focus management** | Window is `focusable: false` (CONTEXT.md locked), so the window does not enter the OS focus chain. The settings popover, when opened, becomes a child window with `focusable: true` so keyboard navigation works within it; closing returns focus to the launching app (terminal/IDE). |
| **Color is not the only state cue** | Each state has a distinct *shape* signal: idle = breathing solid orb; listening = pulsing solid orb with waveform; processing = rotating ring (no fill); speaking = pulsing solid orb with waveform; error = static ring (no fill) + banner. Shape + motion differentiate even for users who cannot perceive the accent color. |

## 6. Permission Flow (UI-07)

Wireframe-level spec for `<PermissionOverlay>`. Three states surfaced when `systemPreferences.getMediaAccessStatus('microphone')` returns:

### State: not-determined

The default state on a fresh macOS install. **No overlay renders** — we defer the prompt until the user's first hotkey press, at which point main calls `systemPreferences.askForMediaAccess('microphone')` and the OS native prompt appears. The user experiences this as "I press the hotkey, the OS asks me to grant mic, I grant, listening starts."

### State: denied

Full-window overlay (260×260) replaces all other content.

```
┌────────────────────────────────────────┐
│                                        │
│              [mic-off icon]            │  ← centered, 32px, --achilles-error
│                                        │
│      Achilles needs microphone         │  ← heading 15px semibold
│             access                     │
│                                        │
│   Open System Settings → Privacy &     │  ← body 13px regular,
│   Security → Microphone and enable     │     line-height 1.5,
│           Achilles.                    │     padding 16px sides
│                                        │
│    ┌─────────────────────────────┐    │
│    │   Open System Settings      │    │  ← primary CTA button
│    └─────────────────────────────┘    │     `--achilles-listening` fill
│                                        │     50px high, full content width
│                                        │
└────────────────────────────────────────┘
```

| Element | Spec |
|---------|------|
| Mic-off icon | 32×32 SVG, `--achilles-error` |
| Heading | `Achilles needs microphone access` — 15px semibold, `--achilles-text`, centered |
| Body | `Open System Settings → Privacy & Security → Microphone and enable Achilles.` — 13px regular, `--achilles-text`, `line-height: 1.5`, padding 16px on both sides |
| CTA button | `Open System Settings` — 13px medium, white text on `--achilles-listening` fill, 6px corner radius, padding 12px × 24px |

CTA `onClick` emits IPC `open-system-settings` → main runs `shell.openExternal('x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone')` on macOS.

On Windows: main runs `shell.openExternal('ms-settings:privacy-microphone')` (documented but only macOS is verified in Phase 11).
On Linux: main shows a fallback dialog explaining that distro-specific paths vary (PulseAudio / PipeWire); user must enable mic in their OS settings.

### State: restricted

Same overlay as `denied` but with adjusted body copy:

> `Microphone access is restricted by your organization. Contact your administrator to enable Achilles.`

CTA button is hidden (the user cannot self-remediate). Only the icon + heading + body are rendered.

### State transitions

The overlay re-checks `getMediaAccessStatus('microphone')` every 2 seconds while visible. Once status becomes `granted`, the overlay dismisses with a 250ms fade and the UI returns to its previous (or `idle`) state.

## 7. Settings Popover

Minimum viable settings for Phase 11. Larger settings UI (API key, voice ID) is deferred to Phase 12/13 per CONTEXT.md.

### Trigger
- Right-click on the circle, OR click the `⋯` affordance at the bottom-right of the window.

### Position
Anchored to the right of the circle (popover top-left at `circle.center.x + 60, circle.center.y - 50`). If overflow, anchor to the left. The popover is a child `BrowserWindow` (focusable: true) so keyboard focus works.

### Dimensions
220 × 180 px. Surface `--achilles-surface`, 8px corner radius, 1px border `--achilles-border`, drop shadow `0 4px 16px rgba(0, 0, 0, 0.4)`.

### Content

```
┌─────────────────────────────────────┐
│  Settings                       [×] │  ← heading 15px semibold + close button
├─────────────────────────────────────┤
│                                     │
│   Hotkey mode                       │  ← label 11px medium
│   ┌─────────┐ ┌──────────┐         │
│   │ Toggle  │ │ Push-To- │         │  ← segmented control,
│   └─────────┘ │ Talk     │         │     selected state has
│               └──────────┘         │     `--achilles-listening` border
│                                     │
│   Hotkey                            │  ← label 11px medium
│   ┌─────────────────────────┐      │
│   │ ⌘ Shift A  [Change]     │      │  ← display + change button
│   └─────────────────────────┘      │
│                                     │
│   ┌─────────────────────────────┐  │
│   │  Reset window position      │  │  ← secondary button
│   └─────────────────────────────┘  │
│                                     │
└─────────────────────────────────────┘
```

| Field | Behavior |
|-------|----------|
| Hotkey mode | Segmented control between `Toggle` and `Push-To-Talk`. Selection persists immediately to `electron-store.hotkeyMode` via IPC `update-hotkey-config { mode }`. |
| Hotkey capture | Shows current accelerator (`⌘ Shift A` on macOS, `Ctrl Shift A` on Win/Linux). Clicking `Change` puts the button into capture mode (label changes to `Press a key combo…`); the next non-modifier keypress combined with held modifiers is captured. Esc cancels capture. Captured key persists to `electron-store.hotkeyKey` via IPC `update-hotkey-config { key }`. |
| Reset window position | Single click → confirmation `Reset position to default (top-right)?` → on confirm, emits IPC `update-window-position { x: null, y: null }` and main applies default top-right. |

### Esc and close
Esc closes the popover; clicking outside the popover also closes it. The close `×` button is keyboard-focusable as the last tab stop.

### What triggers `error` state in Phase 11
The mocked state machine includes an explicit test seam `__test_inject_error` (IPC) that the Playwright suite uses to drive the error state. Phase 12 wires real error sources:

| Trigger (future) | Phase 11 mock | Banner copy |
|------------------|---------------|-------------|

(Phase 12 will add: STT failure, TTS failure, Claude bridge failure, ElevenLabs auth failure — these use the same `<ErrorBanner>` component with new copy.)

| Aspect | Specification |
|--------|---------------|
| **Position** | `top: 0`, `left: 0`, `width: 260`, `height: 90` |

## 9. Component Contract

React components for `apps/achilles/src/renderer/components/`. All props are TypeScript interfaces. The IPC types referenced are from `@achilles/voice-protocol` (Phase 09).

```typescript
// State enum re-used from @achilles/voice-protocol
type AchillesState =
  | 'idle'
  | 'listening'
  | 'processing'
  | 'speaking'
  | 'error';

// ─────────────────────────────────────────────────────────────
// <FloatingShell>
// Top-level layout container; positions the window-internal regions.
// Owns the routing between normal-layout, permission-overlay, and error-banner.
// ─────────────────────────────────────────────────────────────
interface FloatingShellProps {
  state: AchillesState;
  permissionState: 'granted' | 'not-determined' | 'denied' | 'restricted';
  errorMessage?: string;
  micAmplitude: number;     // 0..1, smoothed RMS
  ttsAmplitude: number;     // 0..1, smoothed RMS
  partialTranscript: string;
  committedTranscripts: ReadonlyArray<{ id: string; text: string; committedAt: number }>;
  hotkeyMode: 'toggle' | 'pushToTalk';
  hotkeyKey: string;
  onCircleClick: () => void;
  onCircleRightClick: () => void;
  onErrorDismiss: () => void;
  onOpenSystemSettings: () => void;
}

// ─────────────────────────────────────────────────────────────
// <ReactiveCircle>
// SVG circle whose scale + color reflect the current state.
// Owns the breathing animation in idle and the amplitude-driven
// scaling in listening / speaking.
// ─────────────────────────────────────────────────────────────
interface ReactiveCircleProps {
  state: AchillesState;
  amplitude: number;        // 0..1; only used when state === 'listening' or 'speaking'
  onClick: () => void;
  onRightClick: (event: React.MouseEvent) => void;
}

// ─────────────────────────────────────────────────────────────
// <Waveform>
// Canvas2D 32-bar visualizer; subscribes to an AnalyserNode.
// In Phase 11 the AnalyserNode is mocked (stub emits deterministic
// patterns). In Phase 12 it's wired to mic stream / TTS playback.
// ─────────────────────────────────────────────────────────────
interface WaveformProps {
  state: AchillesState;
  analyser: AnalyserNode | MockAnalyser | null;  // null = render silent baseline
  barCount?: number;        // default 32
  barWidth?: number;        // default 4
  barGap?: number;          // default 2
  maxBarHeight?: number;    // default 22 (pixels)
}

// MockAnalyser interface (Phase 11 testability seam) — shape matches AnalyserNode
interface MockAnalyser {
  frequencyBinCount: number;
  getByteFrequencyData(array: Uint8Array): void;
}

// ─────────────────────────────────────────────────────────────
// <TranscriptOverlay>
// Renders partial + committed transcripts (LOOP-02). Auto-fades
// idle transcripts after 15 seconds.
// ─────────────────────────────────────────────────────────────
interface TranscriptOverlayProps {
  state: AchillesState;
  partial: string;          // empty string when no partial
  committed: ReadonlyArray<{ id: string; text: string; committedAt: number }>;
  maxVisibleLines?: number; // default 3
  fadeAfterMs?: number;     // default 15000 (LOOP-02)
}

// ─────────────────────────────────────────────────────────────
// <PermissionOverlay>
// UI-07 remediation overlay. Three states.
// ─────────────────────────────────────────────────────────────
interface PermissionOverlayProps {
  permissionState: 'denied' | 'restricted';
  platform: 'darwin' | 'win32' | 'linux';
  onOpenSystemSettings: () => void;
}

// ─────────────────────────────────────────────────────────────
// <SettingsPopover>
// Minimal in-popover settings. Hotkey mode + hotkey key + reset position.
// Rendered as a child BrowserWindow anchored to the circle.
// ─────────────────────────────────────────────────────────────
interface SettingsPopoverProps {
  hotkeyMode: 'toggle' | 'pushToTalk';
  hotkeyKey: string;        // Electron accelerator string (e.g. 'CommandOrControl+Shift+A')
  onHotkeyModeChange: (mode: 'toggle' | 'pushToTalk') => void;
  onHotkeyKeyChange: (accelerator: string) => void;
  onResetWindowPosition: () => void;
  onClose: () => void;
}

// ─────────────────────────────────────────────────────────────
// <ErrorBanner>
// Banner rendered above the circle when state === 'error'.
// ─────────────────────────────────────────────────────────────
interface ErrorBannerProps {
  message: string;
  onDismiss: () => void;
}
```

## 10. Testability (Playwright Headless)

Phase 11 ships against mocked state. The Playwright suite drives the renderer in isolation; NO real Electron app launches in CI (per CLAUDE.md "never run applications automatically" and CONTEXT.md test strategy).

### Data-test selectors

Every component renders a stable `data-testid` attribute. Selectors are part of the contract.

| Selector | Element | Use |
|----------|---------|-----|
| `[data-testid="floating-shell"]` | Top-level wrapper | Root for component tree assertions |
| `[data-testid="reactive-circle"]` | The SVG circle | Click target; state attr probe |
| `[data-testid="reactive-circle"]` + `data-state` | The circle's data attribute | State distinctness assertion |
| `[data-testid="waveform"]` | Canvas element | Bar count + color probe via canvas pixel reads |
| `[data-testid="transcript-overlay"]` | Transcript region | Partial vs committed opacity check |
| `[data-testid="transcript-partial"]` | Partial text element | Opacity = 0.7 assertion |
| `[data-testid="transcript-committed"]` | Each committed line | Opacity = 1.0 assertion |
| `[data-testid="settings-affordance"]` | The ⋯ button | Click → opens popover |
| `[data-testid="settings-popover"]` | Popover root | Visibility + focus-trap assertion |
| `[data-testid="error-banner"]` | Banner | Visibility when state=error |
| `[data-testid="error-banner-dismiss"]` | Dismiss button | Click triggers idle |
| `[data-testid="permission-overlay"]` | Overlay root | Visibility when permission denied |
| `[data-testid="permission-overlay-cta"]` | Open System Settings button | Click triggers IPC |
| `[data-testid="hotkey-mode-toggle"]` | Mode segmented control | Selection assertion |
| `[data-testid="hotkey-key-display"]` | Key display | Captures the accelerator string |

### State distinctness assertion

Each state renders the circle's root with `data-state="{state}"`. The Playwright test reads:

```typescript
await page.locator('[data-testid="reactive-circle"]').getAttribute('data-state');
```

To verify *visual* distinctness (not just DOM-attribute), the suite also reads the circle's computed `background` / `box-shadow` and asserts they differ across states (since each state's accent is a distinct token). This catches regressions where the data-state attribute is set but the CSS class fails to apply.

### Headless build target

A separate Vite entry (`apps/achilles/electron.vite.config.ts` → `renderer.headless`) produces a renderer bundle pre-configured with:
- The preload bridge replaced by a **`MockAchillesBridge`** stub injected via `window.achilles = mockBridge` in the test setup.
- AnalyserNode replaced by a deterministic `MockAnalyser` that emits a sine-wave pattern.
- Window dimensions hardcoded to 260×260 in the Playwright `playwright.config.ts` `viewport`.

The Playwright config:


### Mock state injection via IPC seam

The `MockAchillesBridge` exposes a deterministic API:

```typescript
// Test-only API exposed on window.__mockBridge
interface MockBridge {
  setState(s: AchillesState): void;
  setPermission(p: 'granted'|'not-determined'|'denied'|'restricted'): void;
  emitPartialTranscript(text: string): void;

}
```

The Playwright tests use this to drive scenarios without launching Electron:

```typescript
test('the five states render with distinct visuals', async ({ page }) => {
  await page.goto('/');
  for (const state of ['idle', 'listening', 'processing', 'speaking', 'error'] as const) {
    await page.evaluate((s) => window.__mockBridge.setState(s), state);
    await expect(page.locator('[data-testid="reactive-circle"]'))
      .toHaveAttribute('data-state', state);
    await expect(page.locator('[data-testid="reactive-circle"]'))
      .toHaveScreenshot(`circle-${state}.png`);
  }
});

test('hotkey toggle commits in-flight utterance', async ({ page }) => {
  await page.goto('/');
  await page.evaluate(() => window.__mockBridge.setState('listening'));
  await page.locator('[data-testid="reactive-circle"]').click();
  await expect(page.locator('[data-testid="reactive-circle"]'))
    .toHaveAttribute('data-state', 'processing');
});

test('permission denied renders remediation overlay', async ({ page }) => {
  await page.goto('/');
  await page.evaluate(() => window.__mockBridge.setPermission('denied'));
  await expect(page.locator('[data-testid="permission-overlay"]')).toBeVisible();
  await expect(page.locator('[data-testid="permission-overlay-cta"]')).toBeVisible();
});

test('transcript opacity matches LOOP-02 spec', async ({ page }) => {
  await page.goto('/');
  await page.evaluate(() => {
    window.__mockBridge.setState('listening');
    window.__mockBridge.emitPartialTranscript('hello wor');
  });
  const partial = page.locator('[data-testid="transcript-partial"]');
  await expect(partial).toHaveCSS('opacity', '0.7');
  await page.evaluate(() => window.__mockBridge.emitCommittedTranscript('hello world'));
  const committed = page.locator('[data-testid="transcript-committed"]').last();
  await expect(committed).toHaveCSS('opacity', '1');
});
```

### Visual diff vs DOM-attribute assertion

Both strategies are exercised:
- **DOM-attribute** (`data-state="X"`) is the **primary** assertion — fast, reliable, no flaky pixels.
- **Visual screenshot diffs** (`toHaveScreenshot`) run on the five state circles only; they serve as a regression guard for color/scale token drift, not as the primary state check.

- `apps/achilles/test/e2e/` — Playwright specs
- `apps/achilles/test/fixtures/` — mock amplitude patterns, mock transcripts
- `apps/achilles/test/unit/` — Vitest specs for pure helpers (reducer functions, IPC schemas)

### CI integration
- `vitest.workspace.ts` adds a `phase-11-unit` project pointed at `apps/achilles/test/unit/**`.
- A new `playwright.config.ts` project `achilles-renderer` runs the e2e suite headless against the Vite-served headless bundle.
- `npm test` triggers both. No Electron binary is launched.

## Token-Driven Theming for Future Phases

All visual decisions above are encoded as CSS custom properties in `apps/achilles/src/renderer/styles/tokens.css`. Phase 12+ consumers can override the entire color palette by re-declaring the tokens at `:root` in a theme file, without touching component source. The contract:

| Token category | Override path |
|----------------|---------------|
| Color | `:root { --achilles-listening: #yourcolor; }` etc. |
| Spacing | `:root { --space-md: 18px; }` etc. (resampling will affect the layout grid — accepted breakage; Phase 11 fixed pixels in components only as fallbacks) |
| Motion | `:root { --motion-duration-state: 200ms; --breathing-period: 2500ms; }` |
| Typography | All sizes go through `var(--font-size-*)`. The system font stack itself is in `--font-family` and can be replaced. |

This means Phase 13 distribution can ship a "light desktop" theme variant without code changes, and Phase 14 hardening can theme error states more aggressively.
