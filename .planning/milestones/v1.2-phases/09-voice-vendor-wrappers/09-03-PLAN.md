<objective>
Build `@achilles/voice-tts`: the main-process ElevenLabs Flash v2.5 streaming TTS client. Accepts a `keySource` callback for the API key (the actual key reader is provided by the consumer — in Phase 11 it will be Electron `safeStorage`; in tests it is a stub). Opens a WebSocket to the ElevenLabs Flash v2.5 stream-input endpoint with `chunk_length_schedule: [80, 120, 160, 220]`, validates the outbound URL via `assertElevenLabsHost`, and emits sequence-numbered audio chunks parsed through `TtsChunkSchema` from `@achilles/voice-protocol`. A `SequenceBuffer` utility detects out-of-order arrival and gaps so downstream playback (Phase 11 renderer) can preserve arrival order. A sequence-numbered chunk fixture is replayed in scrambled order to prove the ordering guarantee without requiring real audio playback.

Purpose: SAFE-03 is the explicit ownership of this plan — every outbound URL from voice-tts (and conceptually voice-stt; the allowlist matcher itself lives in voice-protocol, this plan exercises it for the TTS path) is denied unless it matches an ElevenLabs hostname. PITFALLS #5 (model lock to eleven_flash_v2_5), #6 (chunk ordering + chunk_length_schedule), and #22 (API key never leaves main — keySource is injected, never stored in the package itself) are mitigated. The 30-second narration fixture + scrambled-order replay test is the headline ROADMAP success criterion for arrival-order playback.

Output: A buildable, testable wrapper package the Phase 11 main process and Phase 12 orchestrator can wire end-to-end.
</objective>

<!-- ElevenLabs Flash v2.5 stream-input protocol facts (from STACK.md + ARCHITECTURE.md HIGH confidence) -->
- SDK package: @elevenlabs/elevenlabs-js@2.51.0 (main process; Node 15+)
- WS endpoint: wss://api.elevenlabs.io/v1/text-to-speech/{voice_id}/stream-input?model_id=eleven_flash_v2_5
- Authentication: xi-api-key header (the API key is loaded by the consumer's keySource callback; the package never persists it)
- Recommended chunk_length_schedule: [80, 120, 160, 220]
- Output formats: mp3_44100 (default), pcm_16000 (lower latency, used by renderer)
- Multi-context WebSocket exists but is OUT OF SCOPE for v1.2 per CONTEXT.md (defer to v1.3)
- Model constant: eleven_flash_v2_5 (CONTEXT.md decisions: locked; eleven_turbo_v2_5 is DEPRECATED and forbidden)

<!-- Suggested SequenceBuffer behavior (PITFALLS #6) -->
- Accepts items with monotonic sequence numbers, possibly out of arrival order
- Emits items in monotonic order via an async iterable / event listener
- Detects gaps (e.g. received 0, 2 without 1) and surfaces a gap event without dropping the buffered higher-sequence items
- After a gap-resolution timeout, optionally surfaces the higher-sequence items even if a gap remains (configurable; v1.2 default is "wait")
