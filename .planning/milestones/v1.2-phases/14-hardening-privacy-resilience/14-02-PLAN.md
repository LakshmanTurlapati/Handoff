## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Main → Disk | TranscriptStore writes JSONL under ~/.achilles/transcripts/; only main writes |
| CLI → Disk | `achilles transcripts purge / list` reads + deletes files; runs OUTSIDE the Electron process |
| Main → Renderer | IPC_TRANSCRIPT_PERSISTENCE_STATE broadcasts the enabled flag for the UI affordance |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-06 | Information disclosure | persisted JSONL files | mitigate | Default OFF — structurally enforced by TS10 (writeFileImpl spy never called when enabled=false); files go under ~/.achilles/transcripts/ (per-user OS perms); on-screen RecordingIndicator visible whenever persistence is active |
| T-14-07 | Information disclosure | log lines during append / purge / list | mitigate | NO transcript content in any log line; only filenames + byte counts + line counts. TS9 + grep guard in Task 1 verify command. |
| T-14-08 | Tampering | purge command on operator request | accept | Purge is an intentional destructive operation invoked by the user; we surface the deleted count + bytes so they can confirm |
| T-14-09 | Tampering | external process writing rogue JSONL into transcripts dir | accept | The store is for the user's own persistence; an external attacker who can write under ~/.achilles/transcripts/ already owns the user's home dir. Out of scope. |
| T-14-10 | Denial of service | unbounded JSONL growth | mitigate | Retention sweep at construction time (default 30 days); per-day filename rotation caps file size in practice; purge subcommand for explicit cleanup |
| T-14-11 | Repudiation | persisted user utterances | accept | The user opted in via `--save-transcripts`; the RecordingIndicator UI makes the active state impossible to miss. No off-host transmission. |
| T-14-12 | Information disclosure | raw audio | mitigate | Plan 14-02 does NOT persist any audio. `--debug-audio` is a separate flag deferred to a follow-up (NOT in this plan). If a future contributor adds audio persistence, the SAFE-02 indicator + opt-in model is the precedent. |
</threat_model>
