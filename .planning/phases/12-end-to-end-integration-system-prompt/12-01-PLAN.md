From packages/claude-code-bridge/src/extractor.ts:
- export function extractAck(streamText: string): string | null
  - Returns the FIRST sentence (terminated by . ? or !) from streamText, trimmed, capped at 120 chars
  - Returns null when no terminator is present or input is empty
- export function extractSpokenSummary(streamText: string): string | null
  - Returns the contents of the FIRST <spoken-summary>...</spoken-summary> block (non-greedy match across newlines)
  - Returns "" (empty string) when markers present but body empty; null when markers absent
- Module-scoped regex: SPOKEN_SUMMARY_REGEX = /<spoken-summary>([\s\S]*?)<\/spoken-summary>/
- Constant: MAX_ACK_CHARS = 120

The companion.md prompt body MUST instruct the model to emit:
  - Exactly one sentence terminator (. ? or !) on the first acknowledgement line so extractAck captures it
  - Literal opening tag <spoken-summary> and closing tag </spoken-summary> (lowercase, no whitespace inside the angle brackets) so extractSpokenSummary's regex matches
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM narration → spoken output | The model's generated text crosses into the user's speakers. PROMPT-* contracts are the first defence against hallucinated success (#17), long symbol-heavy completion (#16), and verbatim-secret read-aloud (#21). |
| companion.md file → claude --append-system-prompt-file flag | The prompt body becomes part of the system prompt at runtime. The package surface (companionPromptPath) is the trusted handle the orchestrator passes; the file content is the authority. |
| Test fixture content → CI logs | Prompt-injection trigger phrases MUST NOT appear verbatim in test fixtures (committed alongside the prompt body) so a CI log scrape cannot harvest a working injection template. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | companion.md content | mitigate | prompt-content.test.ts CI gate fails the build if word caps, marker syntax, or error-override phrasing drift; the file is in git and reviewed in PR |
| T-12-02 | Information disclosure | secrets in spoken summary | mitigate | prompt body's "Formatting rules" section explicitly forbids verbatim secrets/API keys in <spoken-summary> (PITFALLS #21); Plan 12-02's normalisation layer is the belt-and-braces defence |
| T-12-03 | Repudiation | "I have finished" on failed jobs | mitigate | prompt body "When work fails" section mandates the "I ran into a problem" prefix; Plan 12-04's orchestrator OVERRIDES the LLM output using deriveOutcome regardless (PITFALLS #17 — defence in depth) |
| T-12-04 | Tampering | drift between npm-CLI and skill body | mitigate | PROMPT-01 establishes companionPromptPath as the single source of truth; Phase 13's SKILL.md MUST reference this file via the same path resolution so a CI diff check fails on drift (Phase 13 owns the diff check; Plan 12-01 owns the single-source-of-truth artifact) |
| T-12-05 | Information disclosure | prompt-injection trigger phrases in test fixtures | mitigate | prompt-content.test.ts constructs assertion fixtures via deterministic transforms; no verbatim "ignore previous instructions" string appears in this phase's test files |
| T-12-06 | Denial of service | <spoken-summary> body unbounded | accept | The 40-word cap is enforced by the prompt + Plan 12-02's 600-char pre-TTS hard cap; Plan 12-04's TTS routing enforces the upper bound at the wire layer. Plan 12-01 specifies the contract; downstream plans enforce it at the boundary. |

</threat_model>
