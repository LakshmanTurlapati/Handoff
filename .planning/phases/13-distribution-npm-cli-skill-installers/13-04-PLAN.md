From Pitfall #22 (the tarball-secret scan — quotation):
> Add a release-time check: scan the published tarball for any string matching the project's known key prefix; fail the release if found.

Concrete regex patterns for the scan:
- `sk_[A-Za-z0-9_-]{29,}` — ElevenLabs canonical prefix + sufficient-length value (29+ chars after the prefix accommodates short tokens up to typical 40-char keys)
- `xi-api-key:\s*[A-Za-z0-9_-]+` — header-style key (the underlying HTTP header)
- `xi_api_key=\s*[A-Za-z0-9_-]+` — env-style assignment with value
- `ELEVENLABS_API_KEY\s*=\s*["']?[A-Za-z0-9_-]+["']?` — assignment with a value (the README mentions the env-var NAME WITHOUT a value, which is allowed)
- `sk-[A-Za-z0-9_-]{29,}` — Anthropic-style (Pitfall #22 lists `sk-` as a leak-shape; defensive scan)
- `ghp_[A-Za-z0-9_-]{36,}` — GitHub PAT shape (defensive)
- `github_pat_[A-Za-z0-9_]+` — GitHub fine-grained PAT (defensive)

The README documentation allowlist: the script allows the literal substring `ELEVENLABS_API_KEY` (the NAME) inside `apps/achilles-cli/README.md` content — but if the README contains an `=` sign followed by a non-empty value pattern for that name, that's a fail.
