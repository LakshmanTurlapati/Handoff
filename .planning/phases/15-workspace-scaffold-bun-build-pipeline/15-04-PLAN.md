<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner (CI cloud → workspace tarballs + secrets) | The dual-runtime matrix runs on cloud runners; ensures runtime drift surfaces in CI not in production |
| Compiled binary smoke gate (CI → compiled binary --version) | The smoke gate IS the silent-launch defence — a binary that exits 0 silently fails the step; a binary that prints garbage to stderr also fails the grep -E semver check |
| Operator latency capture (manual command → SUMMARY paste) | Operator-trusted; the figures are observational not authoritative — the CI smoke is the authoritative GATE-04 gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-supply-chain | Tampering (supply chain — CI action versions) | actions/checkout@v4, actions/setup-node@v4, oven-sh/setup-bun@v2 | mitigate | All three actions are pinned to specific major versions (v4 / v2). oven-sh/setup-bun is the OFFICIAL Bun action (per RESEARCH.md §State of the Art); actions/checkout and setup-node are official GitHub-published actions. Bun version is pinned exactly at 1.3.14 (per CONTEXT.md item 4). Node version is pinned at "22" (matches the engines.node floor from Plan 01). `npm ci` (NOT `npm install`) is used in CI so the committed lockfile is the authoritative install source. Phase 19 will add `npm audit signatures` as a publish-gate; Phase 15's CI runs an install + test gate only. |
| T-15-silent-launch | Information disclosure (lack of) | compile-binaries job smoke step | mitigate | EVERY compiled binary (all 5 platforms) is invoked with `--version` immediately after compile; the step asserts (a) non-zero exit fails the step, (b) stdout matches /^[0-9]+\.[0-9]+\.[0-9]+/ via grep -E. A silent-launch regression (binary exits 0 with empty stdout, the v1.2 failure shape) fails the grep -E check and breaks the build. Combined with Plan 01's explicit fatal handlers in src/cli.ts and Plan 03's stdio:"inherit" shim, this is the third layer of the silent-launch defence per CONTEXT.md item 7. Phase 19 layers on the ESLint stdio:"ignore" rule (slot prepared in Plan 01's eslint.config.js). |
| T-15-cross-platform-binary-mismatch | Tampering (resolver mismatch) | compile-binaries runner-to-bun-target mapping | mitigate | The matrix entries explicitly pair native-OS runners with their matching bun --target string (macos-latest = arm64 -> bun-darwin-arm64; macos-13 = x64 -> bun-darwin-x64; ubuntu-latest = x64 -> bun-linux-x64; ubuntu-22.04-arm = arm64 -> bun-linux-arm64; windows-latest = x64 -> bun-windows-x64). Cross-compile from an x86 host to an arm64 binary is documented as supported by Bun (RESEARCH.md §Pattern 1) but the smoke step verifies the binary actually runs on its target architecture by executing it on the matching native runner. Mismatch (a wrong target string paired with a runner) would fail the smoke step because the binary either fails to execute (Exec format error on Linux) or runs but prints the wrong version (very unlikely shape). |
