# Phase 07.1: Codex CLI Handoff Skill Migration - Context

**Gathered:** 2026-05-12
**Status:** Ready for planning
**Mode:** Smart-discuss (infrastructure/migration)

<domain>
## Phase Boundary

Migrate the Codex-facing Handoff surface from the unsupported custom `/handoff` slash-command packaging to an explicit Codex CLI **skill** (`$handoff` / `/skills`), with thread/session binding derived from supported environment variables (`CODEX_THREAD_ID`).

**Scope anchor:** command/skill packaging surface, install helper behaviour, env-derived thread binding, docs and web copy that promise `/handoff`. Out of scope: hosted launch URL consumption, new pairing flows, broader command surface.

</domain>

<decisions>
## Implementation Decisions

### Skill Surface

- **D-01:** The supported invocation is the Codex CLI skill (`$handoff` or via `/skills`). The legacy `/handoff` slash-command path is **removed**, not preserved as a fallback.
- **D-02:** Skill manifest stays at `apps/bridge/resources/codex/skills/handoff/SKILL.md`. The installer copies it to `${CODEX_HOME:-$HOME/.codex}/skills/handoff/`.
- **D-03:** `install-codex-command` becomes a **deprecated alias** that forwards to `install-codex-skill` and additionally removes any stale legacy command files left in `${CODEX_HOME:-$HOME/.codex}/commands/handoff*` and `${CODEX_HOME:-$HOME/.codex}/prompts/handoff*`. No new command files are written.

### Thread / Session Binding

- **D-04:** `handoff codex-handoff` derives the active thread from `CODEX_THREAD_ID`. If absent, return `missing_active_thread_context` with the existing repair guidance — no picker fallback.
- **D-05:** Session id is derived from the thread via existing Codex adapter helpers; no new bridge state is introduced.

### Docs and Web Copy

- **D-06:** README, bridge README, hosted help text, and any onboarding pages stop promising `/handoff` as a slash command. They reference `$handoff` (skill invocation) and `/skills` discovery as the supported entrypoint.
- **D-07:** Older copy that still mentions `/handoff` for narrative/historical reasons may stay only inside changelog/archive context, not in user-facing install instructions.

### Tests

- **D-08:** Unit coverage for the install helper asserts: (a) the skill is written, (b) legacy command/prompt files are removed if present, (c) the deprecated `install-codex-command` alias delegates to the skill installer.
- **D-09:** Unit coverage for `codex-handoff` asserts the `CODEX_THREAD_ID`-only path and the `missing_active_thread_context` failure path.

### Claude's Discretion

- Exact filenames inside the skill directory beyond `SKILL.md` (e.g. `agents/`) are at Claude's discretion as long as Codex's skill loader recognises the directory.
- Exact wording of docs/web copy updates is at Claude's discretion as long as `/handoff` is no longer presented as a supported CLI surface.

</decisions>

## Existing Code Insights

### Reusable Assets (already in place)
- `apps/bridge/resources/codex/skills/handoff/SKILL.md` — skill manifest already authored.
- `apps/bridge/src/lib/codex-command-install.ts` — already exports `CodexSkillInstallStatus` and skill install helpers (`resolveCodexSkillInstallDirs`, `resolveCodexSkillDir`). The legacy command install helpers (`resolveCodexCommandInstallDirs`, `resolveCodexCommandDir`) still exist and should be repurposed for **legacy file removal** rather than writing new command files.
- `apps/bridge/src/cli.ts` — `install-codex-command` already marked as "Deprecated alias for install-codex-skill" (line 35). Case handler at line 120 needs to confirm it forwards to skill install and runs legacy cleanup.
- `apps/bridge/src/cli/codex-handoff.ts` — already reads `process.env.CODEX_THREAD_ID` and returns `missing_active_thread_context` when unresolved. Confirm session derivation is `CODEX_THREAD_ID`-only.

### Established Patterns
- XDG/Codex install paths resolved via `CODEX_HOME` then `$HOME/.codex` fallback.
- Fail-closed error contracts with repair-guidance constants (see `codex-handoff.ts` error map).
- Tests live alongside under `apps/bridge/tests/unit/` (e.g. `codex-command-install.test.ts`, `codex-handoff-command.test.ts`).

### Integration Points
- Install commands: `handoff install-codex-skill` (new canonical), `handoff install-codex-command` (deprecated alias).
- Runtime command: `handoff codex-handoff --format json` invoked by the Codex skill.
- Docs surfaces: `README.md`, `apps/bridge/README.md`, any `/handoff` references in `apps/web/` user-facing copy.

## Specific Ideas

- The phase is largely a **cleanup + docs** sweep; most code already targets the skill surface (see 06–07 SUMMARYs). Plans should be scoped to verify-and-finish rather than greenfield build.
- Plan split should track the three plan stubs already in ROADMAP:
  1. Package the explicit `$handoff` Codex skill and update install aliases (verify skill install + legacy removal).
  2. Resolve Codex CLI thread/session context from supported env bindings (verify `CODEX_THREAD_ID`-only path; remove any unsupported discovery).
  3. Update docs, web copy, and tests to match the skill-based invocation.
