<objective>
Implement the latency probe (LOOP-06) — a thin observability layer over the session.ts state machine.

The probe records timestamps at the seven named voice-loop stages, computes per-stage durations and end-to-end speech-end → first-audible-byte latency, maintains a rolling 20-utterance window with P50 / P95 stats, and surfaces them via:
  (a) `[achilles-latency]` console log lines per utterance when `--debug` is active (ACHILLES_DEBUG=1)
  (b) An optional JSON file written to disk so the offline `achilles latency --report` CLI subcommand can read samples without an Electron round-trip.

Purpose: LOOP-06 is the phase-level success criterion that verifies the conversational-feel latency budget (P50 < 1 s, P95 < 1.5 s). Until the probe exists, the budget cannot be measured.

Output:
  - apps/achilles/src/main/latency-probe.ts + .test.ts — pure module + rolling-window + percentile helpers
  - apps/achilles-cli/src/commands/latency.ts + .test.ts — offline report subcommand (replaces stub-status of the latency placeholder slot)
  - session.ts + index.ts — wires probe at the seven stage boundaries
  - apps/achilles-cli/src/cli.ts — `--debug` global flag + `latency` subcommand routing
  - vitest.workspace.ts — phase-14-unit project entry

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer → Main | Transcripts arrive via IPC; latency probe records stage timestamps only — never receives transcript content |
| CLI process → Spawned Electron | The `--debug` flag passes through as ACHILLES_DEBUG env var; main reads it to enable the probe |
| Main process → Disk | LatencyProbe writes a JSON sample file under app.getPath("userData") for offline `achilles latency --report` |
| Offline CLI subcommand → Disk | `achilles latency --report` reads the sample file written by main; if a malicious process tampers with the file, the worst case is a malformed P50 number |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Information disclosure | latency-probe.ts log line | mitigate | The log line includes per-stage durations + utteranceId only — NEVER transcript text, accumulatedText, payload.text, or API key. Verified by grep guard in Task 1 verify command. |
| T-14-02 | Information disclosure | latency-samples.json on disk | mitigate | The persisted JSON contains only timing numbers + utteranceId UUIDs; no transcript, no audio, no key. File path is under app.getPath("userData") (per-user OS dir, default 700 perms). |
| T-14-03 | Tampering | latency-samples.json | accept | If a malicious local process overwrites the file, the impact is a bogus P50/P95 in the offline report. No security boundary is crossed — the file is informational only and never drives runtime decisions. |
| T-14-04 | Denial of service | unbounded rolling window | mitigate | maxWindow=20 is a fixed FIFO; size is constant per process. recordStage on an active sample is O(1); finalizeSample is O(maxWindow) for sort/percentile. |
| T-14-05 | Repudiation | probe debugEnabled toggle | accept | A user who enables `--debug` opts into the diagnostic log; the log path is documented in CONTEXT.md. No off-host telemetry. |
</threat_model>
